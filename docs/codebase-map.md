### Data

- Storage: `app/data/<collection>.json`, an array of objects with integer `id`s, rewritten
  in full on save. There is no locking. `payments_unmatched` and `customer_credits` are
  created at runtime.
- Dates are stored as `YYYY-MM-DD` strings. Audit `ts` is a full ISO timestamp.
- Money is stored as integer kopecks in `*_kopecks` fields.
- Inputs use other formats. KB-2 bank statement: `DDMMYYYY` dates, amounts in kopecks.
  Price import: hryvnia strings such as `"12,50"`.

### Where dates and money are formatted

- `lib/format.js` `formatDate` returns **`MM/DD/YYYY`**. It is called directly by invoice
  HTML (`invoices/render.js`) and reminder emails (`notifications/reminders.js`). It is
  called **indirectly** by the accounting CSV: `export/accounting.js` resolves
  `format['format' + col.type]`, and `config/export-columns.json` declares the `Date` type.
  A grep for `formatDate` does not find this third caller.
- `formatMoney` (`"1 234,50"` plus the hryvnia currency suffix) is used by invoice HTML and reminders. `formatDecimal`
  (`"1234.50"`) is used by the CSV.
- Several modules have their own copies instead of the shared helpers: `fmtAmount` in
  `reports/table.js`, `customers/index.js`, `catalog/price-import.js`,
  `bin/import-statement.js`, `discounts/index.js` (dead) and `legacy/templates.js` (dead,
  next to a `dmy` helper that produces `DD.MM.YYYY`). Report text prints raw ISO dates.
  `catalog/price-import.js` builds dates in local time, while the rest of the app uses UTC.

## 4. Conclusion

Of the 15 claims about the code, 14 are correct and one is an omission. The agent did not list
the old admin UI as a consumer of the API, although it printed all three comments that name the
UI (claim 17). The transcript does not show why. In each of those places the UI is mentioned in
passing, to explain a detail (a string format, the language of the messages, a row limit), and
not described as an integration. The omission does not change the scope of BILL-482: no `/api/*`
response passes through `lib/format.js`, so the admin UI gets stored `YYYY-MM-DD` dates. It
would matter for a change to the customer totals in `lib/customers/index.js`.

The other two wrong claims are in the agent's report about itself. It described its
navigation as "mostly searching", while the transcript shows it bulk-read the files first and
grepped later (claim 15). It also reported 41 files, while its own list names 52 and `app/`
has 52 non-test, non-data files (claim 16). The file count was
first copied into section 1 without a check and was corrected on review against the
transcript. A self-report is a claim like any other; the navigation cost in section 1 is now
taken entirely from the transcript.

The agent did not adopt the out-of-date
`app/docs/ARCHITECTURE.md` (May 2019): it stated that Express, MongoDB, Handlebars, port 3000
and "only SMTP" are obsolete, and it cited the code for each point (claims 5–7). Two traps
were found and reported correctly:

- **A comment that lies.** `lib/format.js:27` says `formatDate` returns ISO, but the code at
  line 33 returns `MM/DD/YYYY`. An agent that trusted docstrings or ARCHITECTURE.md would have
  assumed ISO (claim 1).
- **A caller that grep for the name does not find.** The accounting export reaches
  `formatDate` through `format['format' + col.type]` and the `Date` type in
  `config/export-columns.json` (claim 2). This caller decides the scope of BILL-482: the same
  function feeds the customer-facing invoice and reminders and the machine-read Oblik-Plus
  CSV, and Oblik-Plus must keep `MM/DD/YYYY`. No seeded test covers this CSV (claim 14), so
  a change to its dates would not turn any existing test red.

These claims were chosen as the riskiest for three reasons:

1. They are the claims where documentation and code could disagree (ARCHITECTURE.md, the
   `formatDate` docstring, oblik-plus.md).
2. They decide the impact of the ticket: who calls the formatter, and what each consumer
   expects.
3. They label code as dead or alive, which is easy to infer wrongly from comments alone.

Every check in that third group used `grep` over module names and call sites rather than the
comments. A `require(` pattern alone is not enough here, because `server.js` loads route
modules from a list of strings (claim 11).

One limitation remains. The Oblik-Plus date requirement (claim 4) rests on a 2021 integration
document. The code is consistent with it, but the external system cannot be checked from this
repository.

## 3. Data storage

- **Location and format.** One file per collection: `data/<name>.json`, each an array of objects with integer `id`s (store.js:14, 24-26). Files are written back as pretty-printed JSON (store.js:116).
- **No safety nets.** There is no locking. Cross-process races are acknowledged in comments at payments/index.js:10-12 and audit/retention.js:7-10.
- **Files on disk:** customers, products, orders, invoices, payments, price_history, stock.
- **Created at runtime:** `payments_unmatched` and `customer_credits` (payments/index.js:18-19). A missing file loads as an empty array (store.js:32-34).
- **Other outputs:** `out/audit.log` (JSON lines) and `out/audit-archive/YYYY-MM.jsonl` (audit/index.js:5-10). `out/` does not exist yet.
- **Dates** are stored as `YYYY-MM-DD` strings (store.js:9). Examples: `issued_at`, `due_at`, `paid_at`, `created_at`, `changed_at`, `updated_at`. Audit `ts` is a full ISO timestamp.
- **Money** is stored as integer kopecks in `*_kopecks` fields (store.js:9; e.g. `total_kopecks: 579300` in invoices.json).
- **Inputs:**
  - Bank statement (KB-2, fixed width): `DDMMYYYY` dates, amounts in kopecks (payments/statement.js:14-22, 58).
  - Price import: hryvnia strings such as `"12,50"` (catalog/price-import.js:45-52).

## 4. External integrations (who consumes the output)

1. **Облік-Плюс (accounting).**
   - File: `out/export/oblik-YYYY-MM-DD.csv`, which their server collects at 06:00 (docs/integrations/oblik-plus.md:5-11; bin/nightly-export.js:24).
   - Format: UTF-8, `;` separator, CRLF line endings, header row first (export/accounting.js:12-13).
   - Dates must be **`MM/DD/YYYY`**; amounts like `1234.50`; text must contain no `;` or line breaks (oblik-plus.md:23-25).
   - Columns and their types come from config/export-columns.json; type `Date` maps to `formatDate`, `Decimal` to `formatDecimal`, `Text` to `formatText` (accounting.js:30).
   - If a date is in the wrong format, Облік-Плюс silently skips that row; this already caused an incident in February 2021 (oblik-plus.md:29-35).
2. **SMTP relay.** Reads plain-text emails written to `out/mail/<date>-<kind>-<id>.txt` (bin/send-reminders.js:24-25; config/default.json:8).
3. **Monthly report email.** Cron stdout goes to the director and accounting; accounting pastes the fixed-width text into Excel (bin/monthly-report.js:9-10; reports/table.js:5-6).
4. **BI spreadsheet ("Olena", every Monday).** Pulls report JSON from the API (reports/render.js:2-3).
5. **Reverse proxy with LDAP login.** Supplies `x-staff-id` (router.js:91-93).
6. **Inbound only:** the bank's KB-2 statements via an SFTP bridge (payments/statement.js:1-9).
