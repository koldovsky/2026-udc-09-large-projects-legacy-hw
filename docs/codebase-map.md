# Карта кодової бази — `app/`

> Task A. Карту згенерував агент, потім кожне твердження з розділу 3 перевірене
> по коду або командою.

## 1. Як агент будував карту

- **Інструмент / модель:** Claude Code (розширення VS Code), модель Claude Opus 5.5 (`claude-opus-5-5`).
- **Промпт (стисло):** «Прочитай завдання… давай почнемо з завдання А, документи українською».
  Агент сам узяв постановку з `docs/walkthrough.md`: точки входу (HTTP, cron, CLI),
  модулі, дані, зовнішні інтеграції, де форматуються дати й гроші.
- **Вартість навігації:**
  - **виклики інструментів:** ~44 на Task A, з них 3 невдалі: `git` немає в PATH;
    ripgrep не підтримує look-ahead; PowerShell обрізав лапки в `node -e`.
    Плюс 5 викликів до Task A на читання файлів курсу;
  - **файли:** ~24 прочитано повністю, ще ~26 частково (лише перші 22 рядки
    заголовного коментаря або перші 40–75 рядків), разом ~50 з 86 файлів `app/`;
    тести й `data/*.json` повністю не читались;
  - **токени:** лічильник Claude Code за всю сесію до цього моменту показує
    **In: 174 · Out: 103.0k**; індикатор ліміту — **4 %**.
    - **Out ≈ 90 тис. — частка Task A** (оцінка агента). Решту ≈ 13 тис. забрали
      короткі відповіді поза Task A: огляд завдань, питання про ліміт, правки.
      На Task A припадають міркування між ~44 викликами, параметри викликів і
      сам документ: українська мова токенізується «дорожче», файл займає ~10 тис.
    - **In: 174** — лише некешований вхід, тобто повідомлення користувача.
      Контекст розмови (прочитані файли, результати команд) іде як кешоване
      читання, і лічильник його не показує. Контекст ріс від ~20 до ~75 тис.
      токенів за ~44 виклики, тож кешованого читання набігло **≈ 2 млн токенів**
      (оцінка: 44 × ~45 тис. у середньому).
- **Читав усе підряд чи шукав?** Шукав, у такому порядку:
  1. документація системи (`app/docs/*`, `app/README.md`) як набір тверджень для перевірки;
  2. точки входу (`server.js`, `package.json`, `bin/*`, `config/*`);
  3. `lib/format.js` і `grep` по `format*` та `require(...format)`;
  4. граф `require` по всьому репо (`grep "require('."`), з якого видно живі й мертві модулі;
  5. лише заголовні коментарі решти модулів;
  6. прогони коду в пам'яті (`node`, скрипт у scratchpad, без запису в `out/`),
     щоб побачити реальний вихід рахунку, листа й CSV.

  Повністю прочитано тільки те, що стосується дат, грошей і точок входу.

### Дані

- **Сховище:** JSON-файли в `app/data/` (`customers`, `products`, `orders`, `invoices`,
  `payments`, `stock`, `price_history`); відсутня колекція читається як `[]`.
  Ні MongoDB, ні іншої БД немає.
- **Дати:** рядки `YYYY-MM-DD` в усіх `data/*.json`. Перевірено: жодного не-ISO
  значення в полях `*_at` / `*date`.
- **Гроші:** цілі копійки (`*_kopecks`) усюди.
- **Згенероване:** `app/out/` (export, mail, audit.log) у `.gitignore`.

### 3c. Попутні спостереження (у карту не входять, тікету не стосуються)

Їх не виправляємо, бо це поза тікетом. Записані як ризики.

- `formatDate(new Date(2026, 2, 9))` з **локальною** датою в Києві повертає
  `03/08/2026` (на день раніше), бо `format.js` бере `getUTC*`. Перевірено
  прогоном. Зараз нічого не передає туди `Date`, лише ISO-рядки.
- `bin/nightly-export.js:12`: `today` береться за UTC. О 02:30 за Києвом це ще
  попередній день за UTC, тому файл може називатися вчорашньою датою.
  Висновок зроблено з коду, прогоном не перевірявся.
- У CSV потрапляють **скасовані** рахунки, фільтруються лише `draft`
  (`accounting.js:52`): 36 рахунків, з них 3 скасовані, дають 37 рядків CSV
  разом із заголовком.
- `server.js:25-27` мовчки ковтає `MODULE_NOT_FOUND`: якщо файл routes
  перейменувати, маршрути просто зникнуть без помилки.
- Прапор `newAgingBuckets` у `config/features.json` ніде не читається.

## 4. Висновок

**Одна помилка, знайдена пізніше, у Task B: твердження №4.** Агент написав, що
формат дати не фіксує жоден тест, і «довів» це `grep`-ом, який не знаходить
екрановані слеші. Насправді `test/invoices.test.js:41-42` фіксує `03\/09\/2026`.
