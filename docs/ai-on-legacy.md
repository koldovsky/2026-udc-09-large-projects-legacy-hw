# Де агент помилявся на legacy-коді

> Task D. Три конкретні випадки з цієї роботи; виправлення внесені в документацію або тести.

## Випадок 1 — внутрішній import сплутав із живим legacy-шляхом

- **Що просили:** у Task A визначити живі та мертві/legacy модулі застосунку.
- **Що агент сказав або зробив:** у першій версії `docs/codebase-map.md` написав, що `lib/legacy/templates.js` і `pdf-client.js` мають «активні імпорти».
- **Як помітили:** звірили граф залежностей із переліком `MODULES` у `app/server.js` і CLI у `app/bin/`; жоден активний entry point не підключає `pdf-client.js`. Є тільки внутрішній import templates з самого `pdf-client.js`.
- **Чому він так вирішив:** пошук показав `require('./templates')` у PDF-клієнті, і агент прийняв внутрішній зв'язок між двома legacy-файлами за активне використання застосунком. Стара архітектурна документація також описує PDF рендеринг як живий.
- **Як виправили:** у карті зазначили, що це збережений legacy-код без підключення до поточних server/CLI шляхів; одноразову `mongo-migrate.js` окремо позначили за її коментарем.

## Випадок 2 — висновок про один API поширився на всі API

- **Що просили:** у Task B перелічити місця, які зміняться від форматера, та шляхи, що не зміняться.
- **Що агент сказав або зробив:** у першому `docs/impact.md` написав, що `GET /api/invoices` «та інші API» повертають ISO-дати напряму.
- **Як помітили:** перевірили формулювання проти конкретних route handlers: пряме повернення збережених дат підтверджене для `GET /api/invoices`, але з цього не випливає поведінка інших ресурсів.
- **Чому він так вирішив:** узагальнив знайдений шлях рахунків на решту HTTP API, не перевіривши кожен handler.
- **Як виправили:** звузили твердження в `docs/impact.md` до `GET /api/invoices` і додали, що кожен інший API треба перевіряти окремо.

## Випадок 3 — тест зафіксував випадкову позицію рядка

- **Що просили:** у Task B закарактеризувати текст нагадування до зміни форматера.
- **Що агент сказав або зробив:** спершу додав у `app/test/date-consumers.test.js` перевірку, що фраза починається рівно на символі з індексом `76`.
- **Як помітили:** переглянули твердження до запуску suite: позиція не є контрактом формату дати та залежить від довжини імені/тексту. Очікувану дату можна перевірити за її змістом.
- **Чому він так вирішив:** агент надмірно конкретизував тест, механічно вибравши позицію під поточний fixture замість перевірки потрібного фрагмента виходу.
- **Як виправили:** замінили magic index на перевірку наявності повної фрази з датою; characterization-тести пройшли на незміненому коді до Task C.

## Висновок

Найбільший ризик у цьому репозиторії — вважати наявність файла або внутрішнього `require` доказом активного шляху, а також переносити властивість одного API на інші. Для перевірки треба простежити import до entry point і підтвердити кожне узагальнення конкретними handlers та тестами.
