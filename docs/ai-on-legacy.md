# Де агент помилявся на legacy-коді

> Task D, частина 1.

Основний агент (Claude Opus 4.6) не зробив значних помилок при аналізі коду,
оскільки читав безпосередньо вихідний код, а не покладався на застарілу
документацію. Нижче — контрольний прогін з найдешевшою доступною моделлю.

---

## Контрольний прогін (Haiku 4.5)

- **Чистий клон:** видалено кореневі `README.md`, `AGENTS.md`, `CLAUDE.md`, `.coderabbit.yaml`, `.github/`, `docs/` (`app/README.md` і `app/docs/` лишились) — так
- **Інструмент і модель:** Claude Code CLI, Claude Haiku 4.5 (найдешевша модель в Claude Code)
- **Промпт:** лише тікет BILL-482 дослівно + «Please implement this ticket. Find the date formatting function, change it to DD.MM.YYYY format. Run `cd app && npm test` to verify tests pass.»
- **Що змінила** (`git diff --stat` і суть):
  ```
  app/lib/format.js           | 4 ++--   (змінив formatDate: MM/DD/YYYY → DD.MM.YYYY)
  app/test/invoices.test.js   | 4 ++--   (оновив regex у тесті рахунків)
  ```
  Усього 2 файли, 4 вставки, 4 видалення. Мінімальний диф — але пропустив критичне.
- **Що сказала про результат:** «The date format change applies to: Invoice display (HTML templates), Payment reminder emails (via shared formatDate function), **Any other date displays using this function**.» — надто впевнена; не перевірила, хто ще викликає цю функцію.
- **Чи змінився вихід, який читає інша система?** **Так.** CSV-експорт для «Облік-Плюс» тепер видає `09.03.2026` замість `03/09/2026`. Перевірено:
  ```js
  var csv = accounting.buildAccountingFile([invoice], customers);
  // До: "INV-001;03/09/2026;03/23/2026;..." (MM/DD/YYYY)
  // Після Haiku: "INV-001;09.03.2026;23.03.2026;..." (DD.MM.YYYY)
  ```
  Сервер «Облік-Плюс» пропустить ці рядки (він чекає MM/DD/YYYY; мовчки ігнорує
  інший формат — див. `app/docs/integrations/oblik-plus.md:29-31`, інцидент
  лютого 2021).
- **Тести:** 106 зелених, 0 червоних — тести не покривають формат CSV-експорту
- **Висновок:**

  Haiku зробила рівно те, що каже тікет: «здається, це одна функція
  форматування, дрібна правка». Змінила одну функцію, оновила тест, тести
  зелені. Але:

  1. **Не знайшла прихованого споживача** — `export/accounting.js:30` динамічно
     викликає `format['format' + col.type]`, і рядок `formatDate` у коді не
     зустрічається. Haiku навіть не шукала — вона довірилась тому, що тікет каже
     «одна функція».
  2. **Тести не захистили** — засіяні 106 тестів не перевіряють CSV-формат
     експорту. Зелені тести ≠ коректна зміна.
  3. **Не прочитала `app/docs/integrations/oblik-plus.md`** — документ, який
     прямо попереджає: «будь-яка зміна того, як форматуються дати, — спершу
     подивитись, що буде з цим файлом».

  Основний агент (Opus 4.6) уникнув цієї пастки тому, що: (а) шукав не лише
  `formatDate`, а й `require('../format')` — і знайшов `accounting.js`;
  (б) прочитав `export-columns.json` і побачив `"type": "Date"`;
  (в) прочитав `oblik-plus.md` і дізнався про контракт з іншою системою.
  Різниця — не в інтелекті моделі, а в тому, що курсові файли (`AGENTS.md`,
  `walkthrough.md`) підказали шукати глибше.
