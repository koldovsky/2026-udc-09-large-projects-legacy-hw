# Де агент помилявся на legacy-коді

> Task D, частина 1.

## Основний прогін: помилок щодо legacy-коду не було

Основний агент (Claude Code, Claude Opus 5.5) виконав Task A–C без помилок у розумінні системи. Він не переніс у карту твердження із застарілого `app/docs/ARCHITECTURE.md` і знайшов споживача, якого не видно за назвою функції. Це CSV-експорт для «Облік-Плюс», що викликає `formatDate` через `format['format' + col.type]` (`app/lib/export/accounting.js:30`). Агент також залишив цей файл байт-у-байт незмінним. Вигадувати помилки, яких не було, ми не стали.

**Що саме перевірялося і чому це найризикованіше:**
- Твердження зі старої документації перевірено по коду (`docs/codebase-map.md`, розділ 3). Майже всі вони хибні: Express, Handlebars, MongoDB, «усі дати в ISO».
- Список споживачів шукали не за назвою функції, а за імпортом модуля (`grep "require('../format')"`). Так знайшовся непрямий споживач (`docs/impact.md`, розділ 3).
- Вихід для іншої системи перевірено запуском, а не читанням: до зміни записано еталон (`7b57e3f`), після зміни реальний `bin/nightly-export.js` дав файл, ідентичний еталону (`cmp`).

**Дрібні промахи агента (не щодо поведінки системи, а в інструментах):**
- Команда `node --test test/characterization/` (передача каталогу) у Node 23 падає. Агент помітив це з виводу і передав шлях до файлу.
- У новому тесті агент спершу написав регулярний вираз `/09.03.2026/` з неекранованими крапками, які збігаються з будь-яким символом. Сам помітив на перегляді диффу й екранував (`app/test/invoices.test.js:41-42`).
- Після того як історію гілки переписали, в `docs/impact.md` лишився старий хеш коміту. Агент знайшов розбіжність перевіркою (`grep` по файлу проти `git log`) і виправив.

Оскільки основний агент не помилився, нижче — контрольний прогін.

## Контрольний прогін

- **Чистий клон:** так. Локальний клон репо на коміті `7ada5a0` (стан до будь-яких змін учасника). Видалено кореневі `README.md`, `AGENTS.md`, `CLAUDE.md`, `.coderabbit.yaml`, `.github/`, `docs/`; `app/README.md`, `app/docs/` і `materials/` лишились. Історію git обнулено (`git init` + один baseline-коміт), щоб модель не прочитала курсові коміти. До запуску в клоні 106 / 106 тестів зелені.
- **Інструмент і модель:** Claude Code 2.1.292, **Claude Haiku 4.5**  — найшвидша й найдешевша модель, яку пропонує інструмент.
- **Промпт:** лише тікет — дослівний вміст `materials/ticket-BILL-482.md` («Клієнти плутають дати в рахунках… Треба: у рахунках дата має бути в українському форматі — `09.03.2026` (дд.мм.рррр)… Здається, це одна функція форматування. Дрібна правка.» + коментар тімліда).
- **Що змінила:**

  ```
  app/lib/format.js         | 4 ++--
  app/test/invoices.test.js | 4 ++--
  ```

  Змінено **саму спільну функцію** `formatDate` (`app/lib/format.js:33`):

  ```diff
  - return pad(d.getUTCMonth() + 1) + '/' + pad(d.getUTCDate()) + '/' + d.getUTCFullYear();
  + return pad(d.getUTCDate()) + '.' + pad(d.getUTCMonth() + 1) + '.' + d.getUTCFullYear();
  ```

  Плюс JSDoc («DD.MM.YYYY format (Ukrainian style)») і дві очікувані дати в засіяному `test/invoices.test.js`.

- **Що сказала про результат:**
  > «✅ Всі 106 тестів пройшли успішно … ✅ Обидва місця використовують спільну функцію `formatDate()`, тому была одна правка»
- **Чи змінився вихід, який читає інша система?** **Так.** Перевірено запуском `buildAccountingFile` на фікстурах у клоні і `cmp` з еталоном `app/test/golden/oblik-export.csv` (знятим до зміни): `differ: char 82, line 2`. Змінилися **72 клітинки**: усі `DocDate` і `PayUntil` у 36 рахунках, наприклад `INV-2026-00001;03/01/2026;03/15/2026;…` → `INV-2026-00001;01.03.2026;15.03.2026;…`. «Облік-Плюс» з американською локаллю такі рядки **мовчки пропускає** (`app/docs/integrations/oblik-plus.md:29-31`).
- **Тести:** 106 зелених, 0 червоних. На CSV-експорт у засіяному наборі немає жодного тесту, тож регресію нічого не зловило.
- **Висновок:** Haiku зробив рівно те, що підказував тікет («це одна функція форматування»), і повірив цьому без перевірки. Список споживачів він будував пошуком за назвою функції. Цей пошук знаходить два клієнтські місця, але не експорт, бо там функцію беруть як `format['format' + col.type]`. Сигнал був перед очима: у заголовку прочитаного ним `lib/format.js:4` прямо написано «Shared by the invoice renderer, the reminder mails **and the exports**». Але модель не пішла з'ясовувати, які це «exports». Зелені тести вона прийняла за доказ безпеки, хоча саме вихід для іншої системи тестами не покритий.
