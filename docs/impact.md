# Аналіз впливу — BILL-482

> Task B. Заповнюється **до** зміни коду. Скопіюйте у `docs/impact.md`.

## 1. Що саме змінюється

Зміна спільної функції `formatDate` в `lib/format.js` (яка зараз повертає формат `MM/DD/YYYY`, напр. `03/09/2026`) на інший формат. Це вплине на всі місця, що використовують цю функцію для відображення дат людям або іншим системам.

## 3. Як ви їх шукали

1. **Пошук за іменем**: `Select-String -Pattern "formatDate"` — знайшов лише визначення в `lib/format.js:29,77`.
2. **Пошук імпорту format модуля**: `Select-String -Pattern "require.*format"` у `lib/**/*.js` — знайшов 3 файли: `export/accounting.js`, `invoices/render.js`, `notifications/reminders.js`.
3. **Ручний аналіз** кожного з 3 файлів:
   - `accounting.js:30` — `format['format' + col.type]` де `col.type="Date"` з `export-columns.json:3-4`
   - `render.js:21-22` — прямовий виклик `format.formatDate()`
   - `reminders.js:39,45` — прямовий виклик `format.formatDate()`
4. **Пошук тестів**: `Select-String -Pattern "renderInvoiceHtml|buildReminders|buildAccountingFile"` у `test/` — знайшов тести для `renderInvoiceHtml` (invoices.test.js) і `buildReminders` (reminders.test.js). Тест для accounting export **відсутній**.
5. **Перевірка export-columns.json** — підтвердило, що типи `Date` використовуються для `issued_at` та `due_at`.

**Що знайшов пошук за іменем, а що — ні:**
- Пошук `formatDate` **не знайшов** викликів, бо вони робляться динамічно (`format['format' + col.type]`) або через змінну `format` (не статичний рядок "formatDate").
- **Критично**: пошук `formatDate` **НЕ знаходить `lib/legacy/templates.js:180-187`** — там власна функція `dmy()` (формат `DD.MM.YYYY`), зареєстрована як Handlebars-хелпер `'date'`. Вона зовсім не пов'язана з `lib/format.formatDate`.
- Тому довелося шукати імпорт `require('../format')` і аналізувати використання, **АЛЕ** це все ще пропускає власні форматтери в інших модулях.
