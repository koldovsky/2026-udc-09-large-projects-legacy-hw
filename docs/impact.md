## 1. Що саме змінюється

Дати для **клієнтів** (HTML-рахунок, листи-нагадування) стають `дд.мм.рррр` замість `MM/DD/YYYY`. Але всі три
виходи з датами формує одна функція — `formatDate` (`lib/format.js:29-34`). Третій вихід, файл для «Облік-Плюс»,
мусить лишитися **байт у байт**.

**Для Task C:**
- `formatDate` не міняти й не перейменовувати. Її ім'я — це тип `Date` у `config/export-columns.json`, а цей файл
  бухгалтерія править без деплою (`docs/integrations/oblik-plus.md:12-13`).
- Для клієнтів зробити нову функцію і викликати її лише з `render.js` і `reminders.js`.

## 3. Як ви їх шукали

1. **За іменем:** `grep -rn "formatDate" lib bin server.js config` → `render.js`, `reminders.js`. Знайдено лише 2 з 3.
2. **За імпортом:** `grep -rnE "require\([^)]*format" lib bin server.js` → третій імпортер, `export/accounting.js:9`.
3. **Читання імпортера:** `accounting.js:30` бере функцію за іменем із конфігу. Інших таких місць немає:
   `grep -rn "format\[" lib bin server.js` → лише цей рядок.
4. **Точки входу.** Трьох споживачів імпортують `invoices/routes.js`, `bin/render-invoice.js`,
   `bin/send-reminders.js`, `bin/nightly-export.js`. Маршрути рахунків підключаються за рядком (`server.js:24`), а
   битий `require` мовчки їх прибирає (`:25-26`). Тому HTML-тест іде через справжній HTTP.
5. **Наявні тести:**
   - на `formatDate` і CSV — жодного (`grep -rn "formatDate" test --exclude-dir=characterization` → 0);
   - дати фіксує лише `test/invoices.test.js:41-42`, але `grep "03/09/2026"` його не бачить, бо слеші екрановані.

**Висновок:** пошук за іменем пропустив саме той вихід, який не можна ламати. Його знайшов пошук за імпортом.
