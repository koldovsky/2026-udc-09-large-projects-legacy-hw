  мутації, без нових залежностей і без завантажень через `npx`. Скрипт
  (у репо не входить) копіює `app/` у тимчасову теку поза репо і по черзі для
  кожного мутанта:
  1. робить **одну** точну заміну фрагмента коду (якщо фрагмент знайдено не
     рівно один раз, прогін зупиняється, щоб мутант не «вбився» через
     помилку скрипта);

- **Які мутанти вижили і що це каже про ваші тести:**
  - **A1 — фільтр чернеток у CSV для «Облік-Плюс».** Найважливіша знахідка.
    У фікстурах немає жодної чернетки (`docs/codebase-map.md`, № 8), тож
    еталон «байт у байт» фіксує лише те, що є в даних. Якби фільтр зник,
    чернетки почали б потрапляти в облік іншої системи, і жоден тест цього б
    не помітив. Висновок: golden master фіксує **дані**, а не **правила**; для
    гілок коду, яких немає у фікстурах, потрібен окремий приклад.
  - **U5, U6 — крайні випадки `formatDateUa`.** Нову функцію перевіряли лише
    через еталони, а в них дати завжди коректні й завжди «рівна північ UTC».
    Без перевірки `isNaN` рахунок без дати показав би `NaN.NaN.NaN`; з
    локальним часом замість UTC дата «з'їжджала» б на день залежно від
    часового поясу сервера. Для `formatDate` ті самі мутанти (F5, F6) вбивали
    тести, написані в Task B, — для нової функції їх просто не було.
  - **F4, U4 — еквівалентні мутанти, вбити неможливо.** Для будь-якого
    «порожнього» значення (`''`, `null`, `undefined`, `0`, `false`) `toDate()`
    дає `Invalid Date`, і його все одно відсікає наступна перевірка `isNaN`;
    перевірено прогоном по цих значеннях — вихід оригіналу й мутанта
    однаковий (`''`). Тобто `if (!value) return ''` зайвий. Код не змінювали:
    це не частина тікета, а малий диф важливіший.
  - **Обмеження U6/F6:** їх вбиває дата `Date.UTC(2026, 2, 9, 23, 30)`, яка в
    поясах зі зсувом «+» (Київ) вже наступний день. Якщо тести запускати в
    поясі UTC (наприклад, у CI), локальний і UTC-час збігаються, і ці мутанти
    там будуть еквівалентними — але тоді вони й шкоди не завдають.

- **Що додали, щоб їх убити** (лише тести, код `app/lib/` не змінювався;
  `app/test/characterization/date-consumers.test.js`):
  - `formatDateUa: DD.MM.YYYY in UTC` — `09.03.2026`, `31.12.2026`, рядок із
    часом, `Date` о 23:30 UTC → вбиває **U6**;
  - `formatDateUa: empty and broken input give an empty string` — `''`, `null`,
    `undefined`, «не дата», `Invalid Date` → `''` → вбиває **U5**;
  - `Облік-Плюс file: draft invoices are left out` — до фікстур додано копію
    рахунку зі статусом `draft` (у пам'яті, `data/` не змінюється); у CSV її
    немає, і файл дорівнює еталону → вбиває **A1**.

  Після цього: характеризаційних тестів 11 (було 8), увесь набір
  `npm test` → `tests 117, pass 117, fail 0`; прогін 2 — **21 / 23** вбито,
  вижили лише еквівалентні F4 і U4.

## Висновок

- **До мутацій тести здавались повними, але були не такими.** Характеризаційні
  тести з Task B/C ловили кожну зміну, яку я сам передбачав (формат дат,
  CRLF, `;`, «виправлення» дат для «Облік-Плюс», зміну типу в конфігу), але
  пропустили 3 з 21 мутантів, які можна вбити (A1, U5, U6). Інакше кажучи,
  «усі тести зелені» не доводило, що перевірено все, що важливо.
- **Головна прогалина стосувалася іншої системи.** A1 (чернетки потрапляють у
  CSV для «Облік-Плюс») — той самий клас помилки, що й інцидент 2021 року:
  тести зелені, а в облік іде не те. Причина: golden master фіксує лише ті
  гілки, для яких є дані у фікстурах. Урок: для кожного фільтра або гілки, якої
  немає в даних, потрібен окремий приклад.
- **Нову функцію треба тестувати напряму, а не лише через споживачів.**
  `formatDateUa` була покрита тільки еталонами, де дати завжди коректні; її
  крайні випадки (U5, U6) виявилися неперевіреними.
- **Не кожен вцілілий мутант — прогалина в тестах.** F4 і U4 еквівалентні:
  вони показують зайвий рядок у коді, а не слабкий тест. Прибирати його не
  стали — це не частина тікета.
- **Підсумок:** 3 тести, код не змінено; тести вбивають **21 / 23** мутантів,
  а 2 решта принципово невбивні. Ручні мутації обрано замість Stryker, бо це
  23 цільові мутанти за ~2 хвилини прогону без нових залежностей; для ширшого покриття
  (усі оператори в усіх файлах) наступним кроком був би Stryker через `npx`.
