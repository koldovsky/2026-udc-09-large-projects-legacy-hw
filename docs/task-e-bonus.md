## Які мутанти вижили і що це каже про тести

60 мутантів, що пережили тести з Task B:

| Група | К-сть | Що це | Що зробили |
|---|---|---|---|
| **Перевірки в `formatDateUa`** (`format.js:45`, `:47`) | 3 | Порожня чи нерозпізнана дата дала б клієнтові `NaN.NaN.NaN` або сміття замість `''`. `formatDateUa` з'явилась у Task C без власного тесту, а в усіх 36 рахунків є обидві дати, тож ці рядки не виконувались ніколи | **Убито** |
| **Суфікс `'T00:00:00Z'` у `toDate`** (`format.js:20`) | 1 | Без нього `'2026-3-9'` V8 читає як локальну північ: замість `''` виходить дата, на схід від UTC — на день раніша. Стосується і CSV для «Облік-Плюс» | **Убито** |
| **«Сьогодні» за замовчуванням** (`nightly-export.js:12`, `send-reminders.js:12`) | 2 | `toISOString()` без `.slice(0, 10)` дає ім'я на кшталт `oblik-2026-10-05T11:42:07.123Z.csv`. Ім'я файлу — частина контракту з «Облік-Плюс» (`docs/integrations/oblik-plus.md:11`) і з SMTP-релеєм. Усі тести передавали дату, а cron і `npm run export` (`package.json`) — ні: **тести не перевіряли той запуск, що йде в проді** | **Убито** |
| Еквівалентні | 4 | `if (!value) return ''` → `false` (`format.js:35`, `:45`): для будь-якого falsy-значення `toDate` дає Invalid Date, і `''` однаково повертає перевірка `isNaN`. `'utf8'` → `''` у `writeFileSync` (`nightly-export.js:25`, `send-reminders.js:25`): байти ті самі (перевірено) | Вбити неможливо |
| Еквівалентні для правильних дат | 2 | `'T00:00:00Z'` → `''` у `daysBetween` (`reminders.js:9-10`): `YYYY-MM-DD` без часу й так читається як UTC. Різниця лише для дат без нулів, яких немає ні в даних, ні в cron | Не вбивали |
| Вбиває засіяний `test/reminders.test.js` | 3 | Фільтр `draft` у `reminderKind` (`reminders.js:19`): у даних немає чернеток | Уже вбиті повним `npm test` |
| Гілки, до яких не доходять фікстури, поза BILL-482 | 45 | Список нижче | Не вбивали |

Ці 45:

- **`esc()` у `render.js:10-14` (9).** HTML-екранування не зафіксоване: у фікстурах немає `& < > "`. Маршрут
  `/invoices/:number` публічний (`app/AGENTS.md`), тож зламане `esc()` — це XSS у рахунку, і жоден тест цього не
  помітить. **Найважливіший із незакритих — для окремого тікета.**
- **Фільтр `paid` / `cancelled` у `reminders.js:19` (7).** Еталон — один день (2026-03-13), і того дня жоден
  оплачений чи скасований рахунок не стоїть за 3 дні до терміну. Прострочені їх і так відсіює `isOverdue`
  (`lib/invoices/index.js:74`).
- **Відсутні поля (11).** Рахунок без рядків, клієнта чи ЄДРПОУ (`render.js:33,40,41` — 4); клієнт без
  `contact_name` чи `email` (`reminders.js:33,64` — 5); рахунок без клієнта в CSV (`accounting.js:20-21` — 2). У всіх
  12 клієнтів є всі поля.
- **Невідомий тип колонки (`accounting.js:31-32`, 4).** Без перевірки експорт однаково падає, лише з `TypeError`
  замість зрозумілого повідомлення.
- **Помилки (14).** Читання сховища `if (err) throw err` у `bin/` (6) і помилки CLI `render-invoice.js` — usage та
  «no such invoice» (8). З робочими фікстурами недосяжні.

**Що це каже про тести:**

- Golden master фіксує рівно те, до чого доходять фікстури: формат дат і кожен байт виходу — так, гілки для даних,
  яких у фікстурах немає, — ні. 20 % мутантів, що вижили, — це не «20 % коду без тестів», а гілки, до яких не
  доходять дані.
- На шляху дат після доповнення вижили лише еквівалентні мутанти.
