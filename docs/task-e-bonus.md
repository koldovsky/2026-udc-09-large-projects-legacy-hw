# Task E (bonus) — обрано шлях 1

> **Понад шаблон:** четвертий спосіб — LSP, причому у двох варіантах (без `jsconfig.json` і з ним); еталон відповіді зафіксовано **до** запуску агентів; результати ast-grep оркестратор перезапустив сам.

## Шлях 1 — три способи навігації

**Умови експерименту**, щоб порівнювався лише спосіб навігації:

- Чотири незалежні субагенти, однакова модель (Sonnet 5), READ-ONLY. Перші три запущено паралельно, LSP — окремо, після встановлення мовного сервера.
- Код — стан після Task D (коміт `1691356`); код `app/lib` той самий, що після Task C.
- Однакове питання для всіх: «Хто залежить від того, як форматує дати спільний форматер `app/lib/format.js` (`formatDate` і `formatDateUa`)? Для кожного споживача — `file:line`, як він дістається до форматера, точки входу (HTTP / cron / CLI) і хто читає вихід». Про динамічний виклик у питанні нічого не сказано.
- Відмінність лише в дозволених інструментах:
  1. **Текстовий пошук:** тільки `grep`/`rg`, без читання файлів.
  2. **Субагент Explore:** без обмежень, «як зазвичай».
  3. **ast-grep:** пошук лише структурними шаблонами; `Read` — тільки щоб підтвердити знайдене.
  4. **LSP:** лише інструмент `LSP` у Claude Code (`findReferences`, `incomingCalls`, `workspaceSymbol` тощо); `Read` — тільки для рядків, на які вказав LSP; якщо LSP нікуди не веде, агент мав чесно зупинитись.
- **Еталон** (`docs/impact.md` §2 з урахуванням §5): 3 споживачі і 4 точки входу.
  - `invoices/render.js:38-39` і `notifications/reminders.js:40,46` → `formatDateUa`, читає клієнт;
  - `export/accounting.js:30` → `format['format' + col.type]` з типом `"Date"` із `config/export-columns.json:3-4` → `formatDate`, читає «Облік-Плюс»;
  - точки входу: `GET /invoices/:number`, `bin/render-invoice.js`, `bin/send-reminders.js`, `bin/nightly-export.js`.
- **LSP довелося вмикати.** Вбудований `LSP` відповідав `No LSP server available for file type: .js`. Запрацювало з плагіном `typescript-lsp@claude-plugins-official`, глобальним `typescript-language-server` 6.0.1 і **TypeScript 5.9.3**: з TypeScript 7.0.2 (переписаний на Go, без `lib/tsserver.js`) сервер падає з `Could not find a valid TypeScript installation`. В `app/` нічого не встановлено; ast-grep 0.45.3 запускався через `npx`.
- **Вартість:** виклики, токени й час — з лічильника Claude Code по завершенні субагента. «З кешу» — сума `cache_read` із транскрипту; транскрипт її занижує (див. Task A), тож це нижня межа, лише для порівняння.

**Висновок:**

- **Вирішила стратегія, а не інструмент.** Три способи з чотирьох знайшли повну відповідь, бо дійшли до питання «хто підключає `format.js`», а не зупинились на пошуку за іменем. Одна команда `grep -rln formatDate lib bin server.js` повертає лише `format.js`, `render.js` і `reminders.js`, тобто пропускає саме той вихід, що ламається без жодної помилки.
- **Explore — найшвидший і найдешевший:** 1.1 хв і 42k токенів, у 2 рази менше за ast-grep. Досить для першого проходу, але читає файли цілком, і в звіті трапляються неперевірені узагальнення.
- **Текстовий пошук — посередині за вартістю** (2.1 хв, 58k токенів). Механізм знайшов, але лише обійшовши заборону читати файли.
- **ast-grep — другий за вартістю (4.6 хв, 82k токенів), зате єдиний дає вичерпний доказ,** що інших динамічних звертань до `format` і прихованих імпортів немає. Перед правкою контракту з іншою системою потрібен саме такий доказ.
- **LSP — найдорожчий (6.7 хв, 110k токенів), найменш повний і на цьому коді найнебезпечніший.** Без `jsconfig.json` він не бачить викликів через `require`, а з ним для `formatDate` видає впевнене «0 посилань». «Find references» доводить наявність, але не відсутність, і не бачить саме контракт з «Облік-Плюс».
- **Практичне правило для цього репо:**
  - першим проходом — Explore;
  - потім `ast-grep --pattern 'format[$EXPR]'` і `'$OBJ[$EXPR]'` як доказ;
  - LSP — лише для переходу з конкретного виклику до визначення, не для питання «хто залежить»;
  - головна пастка записана в `app/AGENTS.md`.
