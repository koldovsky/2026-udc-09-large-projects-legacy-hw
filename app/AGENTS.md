# Знання для агентів (AGENTS.md)

Цей файл містить неочевидний контекст щодо legacy-коду проєкту, щоб наступні агенти не робили помилок під час навігації та змін.

## Застаріла документація
- `docs/ARCHITECTURE.md` **є неактуальним**. Він згадує MongoDB, Express, Handlebars і генерацію PDF, яких у системі вже немає.
- `app/lib/legacy/*` містить мертвий код (наприклад, `pdf-client.js` та `templates.js`), який не використовується. Не орієнтуйтеся на нього при аналізі системи. Рахунки тепер рендеряться як HTML через конкатенацію рядків у `app/lib/invoices/render.js`.

## Зберігання даних
- База даних відсутня. Усі дані зберігаються у вигляді звичайних JSON-файлів у директорії `app/data/` (управління через `app/lib/store.js`).
- **Дати** в системі завжди зберігаються як рядки у форматі ISO 8601 (`YYYY-MM-DD`). 
- **Гроші** завжди зберігаються та передаються як цілі числа у копійках (ніколи як float).

## Контракти із зовнішніми системами
- **Експорт для бухгалтерії ("Облік-Плюс"):** скрипт експорту `app/lib/export/accounting.js` використовує динамічний виклик методів із `app/lib/format.js` (через `format['format' + col.type]`). Стовпець типу `Date` жорстко очікує формат `MM/DD/YYYY`. **БУДЬТЕ ОБЕРЕЖНІ**: якщо ви змінюєте `format.formatDate()`, ви можете зламати контракт із бухгалтерською системою, яка парсить CSV. Використовуйте окремі функції для відображення дат клієнтам (наприклад, `formatDateUA`).

## Пошук споживачів коду
- У проєкті використовуються динамічні виклики функцій (напр. у `export/accounting.js`). Звичайний текстовий пошук або `grep` за іменами методів (напр. `formatDate`) не покаже всіх залежностей. Завжди перевіряйте експортований об'єкт і де імпортується сам модуль.
